# Mac 串口中转 → Ubuntu ROS 2 → F401 麦轮底盘

想先了解文件夹分类、关键源码职责和阅读顺序，可以先看[工程目录与代码阅读指南](工程目录与代码阅读指南.md)。

当前接法：NUCLEO 的 ST-LINK USB 接 Mac；VirtualBuddy 中的 Ubuntu 24.04 已装 ROS 2 Jazzy。Ubuntu 无需出现 `/dev/ttyACM0`，只需能通过网络访问 Mac。

默认固件已改为 `Core/Inc/robot_app.h` 中的 `ROBOT_APP_MODE=7`。上电、打开中转、网络连接、按蓝色 USER 均不会启动旧路线；蓝色 USER 在此模式仅用于软件停止。旧的 0..6 模式仍保留。四轮接线和轮序不变：A左前、B左后、C右后、D右前；软件数组按 FL/FR/RL/RR。

## 1. 先编译下载新固件（Mac）

1. 关闭电机驱动电源进行下载，NUCLEO 按之前已验证的方式正确供电；不要在本步骤改变电源跳线。
2. CubeIDE 左侧选中 `F401RE_TB6612`，右键 **Refresh**（或 F5），确认 `Core/Src/remote_control.c` 已出现。
3. 点击 **Project → Build Project**，确认 0 errors。新增文件如果没编进来，执行一次 **Project → Clean…** 后重新 Build。无需重配四轮引脚。
4. 沿用之前成功的下载方式把程序下载到板子，若调试停在 `main`，点 **Resume**。确认程序运行后结束调试会话，再启动 Mac 中转。
5. 停止 `screen`、串口终端等占用串口的程序。Mac 中转会独占串口；不要让两个上位机同时控制。

`.ioc` 和源码已同步启用 USART2 global interrupt，优先级 6；TIM9 调速中断仍为 5。USART2 接收只入缓冲，解析与打印在主循环。此步不要求再点击 Generate Code；以后重新生成仍应保留 USER CODE。

下载后用旧串口终端可能看到 `@T,...*XXXX`，这是新的带 CRC 遥测格式。它由中转软件解析，字段含义见 [协议说明](remote-control-protocol.md)。

## 2. 在 Mac 启动中转

Mac 新终端执行：

```bash
cd /Users/glion9527/stm/stm32Projects/F401RE_TB6612
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r host_control/requirements.txt
python3 host_control/mac_gateway.py --serial /dev/cu.usbmodem1103 --bind 0.0.0.0
```

如果改用拓展坞，把串口换为 `/dev/cu.usbmodem1303`。重新插拔后可用 `ls /dev/cu.usbmodem*` 确认。每次新终端都要进入工程并 `source .venv/bin/activate`，环境只需创建/安装一次。

正常显示：

```text
串口握手成功，底盘未使能。
配对码文件：.../host_control/.local/token
配对码（只复制到自己的 Ubuntu）：...
中转已监听 0.0.0.0:8765；连接本身不会使能电机。
```

保持该终端运行。配对码自动生成并保存在本地，已经忽略进 Git；只需复制到 Ubuntu 一次。若提示等待 H/ACK 超时，先确认刚才下载的是 MODE7 固件且板子程序在运行。

## 3. 确认 Ubuntu 可访问 Mac

在 **Ubuntu** 终端执行：

```bash
ip route show default
```

共享/NAT 网络中，输出 `default via` 后的地址通常是 Mac 虚拟网络网关，可先作为候选地址。例如输出 `default via 192.168.64.1 ...`，下面把 `MAC_IP` 换为 `192.168.64.1`。这不是固定值，应以你的输出为准；也可以尝试 Mac“系统设置 → 网络”中显示的本机局域网地址。

先检查 TCP 可达性，不发送运动指令：

```bash
python3 -c 'import socket; s=socket.create_connection(("MAC_IP",8765),timeout=2); print("TCP连接成功"); s.close()'
```

该命令里的 `MAC_IP` 必须替换成实际数字地址。成功只证明网络和端口可通，还需下一步配对。失败时核对中转是否仍运行、是否用了 `--bind 0.0.0.0`、Mac 防火墙是否允许该 Python 接收入站连接。无需先配置跨机器 DDS 发现；当前所有 ROS 节点都在 Ubuntu 内运行，只有 TCP 连接 Mac。

## 4. 把上位机代码放到 Ubuntu

把工程目录复制/同步到 Ubuntu，例如 `~/code/F401RE_TB6612`。至少要包含同版本的 `host_control/` 和 `ros2_ws/`，保持它们并列；无需复制 `.venv`、Debug、Release。可沿用你已有的共享目录、Git 或文件复制方式。下文假设目录为 `~/code/F401RE_TB6612`，不同位置请对应替换。

在 Ubuntu 建立配对码文件：

```bash
mkdir -p /home/glion/code/F401RE_TB6612/.config/f401_robot
nano /home/glion/code/F401RE_TB6612/.config/f401_robot/token
```

把 Mac 显示的配对码单独粘贴一行，Ctrl+O、回车保存，Ctrl+X退出，然后：

```bash
chmod 600 /home/glion/code/F401RE_TB6612/.config/f401_robot/token
```

先只读取反馈，不使能：

```bash
cd ~/code/F401RE_TB6612
python3 host_control/probe.py --host MAC_IP --token-file /home/glion/code/F401RE_TB6612/.config/f401_robot/token
```

成功时每秒打印一组结构化遥测，`armed` 为 `false`，四轮 count/rpm/target/pwm/fault 均可读。按 Ctrl+C 退出 probe，**再**启动键盘或 ROS 桥接；中转只允许一个控制客户端。

## 5. 先验证普通键盘遥控（可作为 ROS 前的独立排查）

先固定底盘并让四轮离地，首次仅点按，检查方向和反馈。电机供电沿用已验证接法，不在这里重接线。

```bash
cd ~/code/F401RE_TB6612
python3 host_control/keyboard_control.py --host MAC_IP --token-file /home/glion/code/F401RE_TB6612/.config/f401_robot/token
```

| 键 | 动作 |
| --- | --- |
| r | 显式使能；本身不会使车轮转动 |
| w / s | 前进 / 后退，默认 0.08m/s |
| a / d | 左移 / 右移，默认 0.08m/s |
| q / e | 逆时针 / 顺时针转，默认 0.25rad/s |
| 0 | 速度归零，保留使能 |
| 空格 | 停止并解除使能 |
| Ctrl+C | 退出并尝试停止 |

终端没有可靠的松键事件：本程序采用 **200ms 无新按键即归零**，点按一次产生一小段动作，长按取决于系统按键重复，初次重复前可能停顿。首次不要求长按连续运动。

切换到需要某些轮子反转的动作前，先按 0 并等车轮完全停稳（初测可等 1 秒）。如果触发 `REJECTED`，整车停止并解除使能，停稳后重新按 r。蓝色 USER、命令过期、通信错误或电机故障也会解除使能，不会自动恢复旧动作；电机故障需排查后复位，程序不会自动清故障。

退出普通键盘程序后，再做下一步 ROS 验证。

若曾在 TB6612 未供电时发送非零速度，可能触发编码器无反馈故障；事后打开驱动电源不会自动清除已锁存故障。先保存 Mac 和 ROS 桥接报错，再退出键盘、桥接、中转，确认驱动已正确上电，复位 NUCLEO 后按顺序重新启动。上电/复位本身不会使能遥控。

Mac 中转遇到拒绝结果时会先确认停止，再回复客户端，避免连续未确认 STOP 被 STM32 的清队列保护丢弃。串口超时日志包含命令、序号、最近反馈与故障值；这类 Mac 端修正只需重启中转，不需要重烧固件或重新构建 ROS 包。

## 6. 构建 Ubuntu 的 ROS 2 包

Ubuntu 执行：

```bash
source /opt/ros/jazzy/setup.bash
cd ~/code/F401RE_TB6612/ros2_ws
colcon build --symlink-install
```

若 `colcon` 不存在，先安装：

```bash
sudo apt update
sudo apt install python3-colcon-common-extensions
```

此 ROS 包依赖 `rclpy`、`geometry_msgs`、`sensor_msgs`、`std_msgs`、`std_srvs`，常规 Jazzy 安装通常已有。若缺少，执行：

```bash
sudo apt install ros-jazzy-rclpy ros-jazzy-geometry-msgs ros-jazzy-sensor-msgs ros-jazzy-std-msgs ros-jazzy-std-srvs
```

## 7. 运行 ROS 桥接与键盘

推荐使用能识别按下/松开的窗口控制。先退出 probe、普通键盘以及旧的 ROS 键盘、桥接，保持 Mac 中转运行。同步 Mac 上更新后的 `host_control/` 和 `ros2_ws/` 到 Ubuntu 的 `~/code/F401RE_TB6612`，保留原来的配对码文件。安装窗口依赖并重新构建一次（新增了窗口入口）：

```bash
sudo apt install python3-tk
source /opt/ros/jazzy/setup.bash
cd ~/code/F401RE_TB6612/ros2_ws
colcon build --symlink-install
```

构建成功后，Ubuntu 终端 1 启动桥接：

```bash
cd ~/code/F401RE_TB6612
bash ros2_ws/run.sh network_bridge --ros-args \
  -p host:=192.168.64.1 \
  -p token_file:=/home/glion/code/F401RE_TB6612/.config/f401_robot/token
```

脚本会加载 Jazzy、工作区和共用网络客户端路径。程序默认读取 `~/.config/f401_robot/token`，上面命令已显式指定你存放在工程内的配对码路径，连接后仍未使能。若提示连接失败，先排查网络/probe占用/配对码，再使用 `/robot/connect` 显式重新连接。

Ubuntu 图形桌面的终端 2 启动控制窗口：

```bash
cd ~/code/F401RE_TB6612
bash ros2_ws/run.sh keyboard_window
```

保持终端1桥接运行。点击新出现的控制窗口，在窗口内按 r 申请使能，松开 r，收到成功回复后再按住 w；松开运动键归零。W/S前后、A/D横移、Q/E旋转、0零速、空格停止并解除使能，键位与普通键盘相同。默认线速度已统一为底盘实测能起步的 0.08m/s，角速度为 0.25rad/s。使能操作本身不运动，故障不会自动清除。

窗口去除终端200ms字符间隔造成的首轮停顿：持续按住时按固定20Hz发送指令，松开约15ms确认后，在下次发布周期归零；焦点离开控制窗口、最小化/关闭窗口会清除运动意图并申请解除使能。切到其他窗口后需要重新有意使能。每次使能后的首次运动开始计时，最多5秒，到时解除使能；自动重复、零速等待和切换运动键不会延长这5秒，松开按键并重新使能才开始下一次。这是当前开发测试窗口的限制。

切换窗口前先松开全部按键。若失焦时仍按着某个方向，窗口会隔离该键，直到在窗口内收到真实松键；如果你在其他窗口已松开，回控制窗口后可点按并松开该方向键一次，再按就能使用。r若无响应，也先松全键、点按并松开r一次，再重新按r，避免把旧自动重复当成新的使能操作。

另有1秒无新键事件的租期和200ms事件循环卡顿检查，防止虚拟机遗漏松键后持续发送旧键状态。VirtualBuddy从Ubuntu切回Mac时是否正确转发松键/失焦仍需实测；若客体仍生成自动重复，绝对5秒上限仍会终止本次控制。ROS的250ms源指令时效、STM32的300ms运动指令超时保持不变。这些都是撤销驱动，车轮仍可能靠惯性滑行。

首次验证四轮悬空，依次测试：长按w超过首次键盘重复延迟、松开w、空格、切换Ubuntu内其他窗口、切回Mac，以及关闭控制窗口。需要某些轮子反向时先释放所有运动键并等停稳，否则可能被底层换向保护拒绝；窗口会停并等待重新使能。

终端点按模式仍可使用 `bash ros2_ws/run.sh keyboard`，它保留200ms无新字符归零，因此长按可能先短暂停一下。这两种输入程序不要同时运行，以免共同发布速度。

ROS 键盘发送的是 `geometry_msgs/msg/TwistStamped`：`linear.x/y` 为 m/s，`angular.z` 为 rad/s，`frame_id=base_link`。桥接默认使用同一类型，队列深度 1，丢弃过期消息和使能前发布的消息。

Ubuntu 终端 3（只观察）：

```bash
source /opt/ros/jazzy/setup.bash
ros2 topic echo /robot/state --field data --full-length
```

也可观察 `/joint_states`：位置单位 rad、速度单位 rad/s，顺序 FL/FR/RL/RR；不把 PWM 假装成扭矩。MCU 原始毫秒数和原始编码器计数保存在 `/robot/state` 的 JSON 中。当前 JointState 使用 ROS 接收时间，尚未做 MCU 时间同步，也没有发布导航用 odom/TF。

需要手动调用服务时：

```bash
source /opt/ros/jazzy/setup.bash
ros2 service call /robot/disarm std_srvs/srv/Trigger '{}'
ros2 service call /robot/connect std_srvs/srv/Trigger '{}'
ros2 service call /robot/arm std_srvs/srv/Trigger '{}'
```

每条分别执行，不要把三个服务作为一个自动启动序列。重新连接后等待停稳，再有意使能。使能成功后只会执行新的速度消息。速度话题类型固定为带时间戳的 TwistStamped，后续接入导航时也需统一发布类型与车身坐标约定。

## 8. 这一阶段的验收

- probe 能读到四轮状态，连接本身不转动。
- r 后分别点按 w/a/q，方向正确，有编码器与轮速反馈；0 和空格停止。
- 对需要反向的动作先归零、停稳，再操作。
- 蓝色 USER 能解除使能；按住按钮无法重新使能。
- 结束键盘节点后零速；退出桥接、暂停虚拟机、拔 USB 等情况下能撤销驱动。先在悬空低速条件逐项验证。
- 重连不恢复旧速度，必须重新显式使能。

通信链路默认20Hz；ROS源消息250ms过期归零，STM32从最后有效运动命令起300ms失效并在10ms控制节拍撤销驱动，原500ms主循环看门狗继续保留。撤销驱动后车轮会滑行，参数不是“300ms物理刹停”的保证。蓝色按钮是软件停止，没有新增硬件急停电路。
