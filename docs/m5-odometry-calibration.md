# M5 轮式里程计标定（2026-11-19）

## 实测数据

| 项目 | 实际值 | `/odom` 实测 | 单次比例 |
|---|---:|---:|---:|
| 直行 | 1.000 m | 0.964 / 0.977 / 0.965 m | 1.0373 / 1.0235 / 1.0363 |
| 横移 | 0.500 m | 0.499 / 0.491 / 0.488 m | 1.0020 / 1.0183 / 1.0246 |
| 原地旋转 | 360.0° | +349.02 / -349.80 / +347.21° | 1.0315 / 1.0292 / 1.0368 |

方向检查：前进 `dx>0`，左移 `dy>0`，右移 `dy<0`，左转 `dyaw>0`，右转 `dyaw<0`，符号正确。

## 结论

- 直行平均比例：**1.0324**
- 旋转平均比例：**1.0325**
- 两者几乎一致，说明主要是轮缘位移尺度偏小；统一缩放轮速即可同时修正距离和由轮速反算的 `yaw`。
- 横移单独比例约 1.015；套用统一比例后 0.500m 的读数为约 0.509m，误差 1.7%，在 M5 的 5% 目标内。

## 代码改动

只改 host 侧里程计，不改固件运动学：

- [host/src/drivers/serial_base.cpp](../host/src/drivers/serial_base.cpp)
- `kOdomWheelScale = 1.0325`
- `kMetersPerCount` 乘以该比例
- `/odom` twist 同样使用该比例

这样不会改变下发给 STM32 的 CMD，只修正 `/odom` 的位姿积分和 twist 尺度；
`/joint_states` 仍使用原始编码器角速度。

## 复测目标

- 直行 1.000m：`dist` 0.95–1.05m；
- 横移 0.500m：0.475–0.525m；
- 原地 360°：355–365°。

## 复测结果（统一比例 1.0325）

| 项目 | 复测值 | 误差 |
|---|---:|---:|
| 直行 1.000m | 1.011 / 1.008 / 1.009m，平均 1.009m | +0.9% |
| 原地 360° | +356.04 / +358.27 / +355.55°，平均 356.62° | -3.38° |
| 横移 0.500m | `dy` -0.502 / -0.498m | 横向误差约 0mm |

横移时 `dx` 约 -0.123m，`dy` 约 -0.500m，说明测试起始车体相对 odom 坐标大约有 13.8° 的航向差，或实际路径不是纯横移；这不是横移尺度问题。横移的 `dy` 已经准确，统一比例不需要再改。

结论：直行误差 <1%，旋转误差 <4°，横移横向误差 <1%，M5 达到目标。
