# 工程目录与代码阅读指南

本工程包含一套运行在 STM32 上的四轮电机固件，以及运行在 Mac 和 Ubuntu 上的控制程序。当前固件选择 `ROBOT_APP_MODE=7`，使用串口遥控；旧的逐轮测试、动作测试和路线模式仍保留在条件编译分支中。

理解工程时先区分三个运行位置：

```text
Ubuntu：ROS 2 键盘节点或其他运动指令发布者
    ↓ /cmd_vel（TwistStamped）
Ubuntu：network_bridge 桥接节点
    ↓ TCP网络上的JSON请求
Mac：mac_gateway.py 串口网关
    ↓ USB虚拟串口上的CRC协议帧
STM32：remote_control → mecanum → motor4 → PWM/方向引脚 → 电机
    ↑ 编码器反馈；STM32生成遥测，经相同链路返回Ubuntu
```

## 一、按用途分类的目录

| 分类 | 目录 | 内容与用途 | 日常阅读与修改位置 |
| --- | --- | --- | --- |
| STM32 固件 | `Core/` | 板上运行的应用、外设配置、头文件和启动代码 | 电机、串口遥控、硬件配置的主要入口 |
| 芯片基础库 | `Drivers/` | ST 的 HAL 驱动以及 CMSIS 芯片/处理器支持文件 | 学习底层实现时查阅，业务逻辑放在 Core |
| Mac 网关与通用客户端 | `host_control/` | Mac 串口网关、网络客户端、普通 Python 键盘控制和协议测试 | 网络与串口之间的转换在这里 |
| Ubuntu ROS 2 | `ros2_ws/` | ROS 包、桥接节点、键盘节点及启动辅助脚本 | ROS 话题、服务和消息映射在这里 |
| 自动测试 | `tests/` | 电机和遥控 C 仿真、ROS 状态与节点测试 | 修改控制逻辑后在电脑验证 |
| 使用与设计说明 | `docs/` | 本指南、遥控操作步骤、通信协议 | 先看目录，再按上手文档操作 |
| 接线资料 | `four_motor_upgrade/` | 当前只保留四路 CubeMX 配置和接线说明 | 查物理接口、引脚、排针和旧升级步骤 |
| STM32 编译输出 | `Debug/` | Makefile、对象文件、依赖、ELF 固件、MAP 和反汇编清单等 | 由 CubeIDE 构建生成，应用源码在 Core |
| Python 本地环境 | `.venv/` | Python 解释器入口、pip 和已安装依赖 | 用 activate 激活；不作为业务源码维护 |
| IDE 设置 | `.settings/` | CubeIDE/Eclipse 的编码、语言分析、外设视图等配置 | 一般通过 IDE 设置修改 |
| Git 历史 | `.git/` | 提交、分支、对象和本地版本库元数据 | 通过 Git 命令管理 |

### Core 内部

| 子目录 | 作用 |
| --- | --- |
| `Core/Inc/` | `.h` 头文件：函数声明、结构体、枚举、常量和编译选项；供其他 `.c` 引用 |
| `Core/Src/` | `.c` 实现文件：初始化、控制算法、串口处理和运行时逻辑 |
| `Core/Startup/` | 上电启动汇编和中断向量表；复位后准备运行环境，再进入 main |

`Core/Inc` 里的声明告诉其他模块“可以调用什么”，对应的 `Core/Src` 实现说明“具体怎么做”。不是每个头文件都单独执行，头文件会在编译时被包含到使用它的源码中。

### Drivers 内部

- `Drivers/STM32F4xx_HAL_Driver/Inc` 和 `Src`：HAL 接口与实现，例如 `HAL_UART_Transmit`、`HAL_TIM_PWM_Start`。
- `Drivers/CMSIS/Include`：Arm Cortex-M 处理器的寄存器、内核和中断操作支持。
- `Drivers/CMSIS/Device/ST/STM32F4xx`：STM32F4 型号对应的寄存器定义和系统支持。

应用先调用 HAL，由 HAL 操作寄存器。通常先理解 Core 中“为什么调用”，再深入 Drivers 中“硬件怎样实现”。

### host_control 内部

| 文件或子目录 | 作用 |
| --- | --- |
| `mac_gateway.py` | Mac 启动入口，读取命令参数，打开串口，创建串口会话并监听 TCP |
| `robot_link/gateway.py` | 实际网关：串口读线程、命令确认、遥测缓存、配对认证和网络请求处理 |
| `robot_link/client.py` | 通用 TCP 客户端，供 probe、普通键盘和 ROS 桥接调用 |
| `robot_link/protocol.py` | CRC 串口帧和 JSON 行的编码/解析、字段校验及速度整数单位 |
| `robot_link/__init__.py` | Python 包入口；把该目录组织为可导入的 robot_link 包 |
| `probe.py` | 查询连接和反馈数据的工具，便于在接入 ROS 前排查链路 |
| `keyboard_control.py` | 不依赖 ROS 的终端点按遥控，直接调用 RobotClient |
| `requirements.txt` | pip 依赖清单，当前主要依赖 pyserial 访问串口 |
| `tests/test_robot_link.py` | 用假串口、进程内 socket 测试协议、网关、客户端和异常流程 |
| `.local/` | 网关运行后生成的本地配对码等私有数据；已通过忽略规则排除出 Git |

`host_control` 中的模块既有 Mac 端服务，也有 Ubuntu 使用的纯 Python 客户端。Ubuntu 的 ROS 桥接复用 `robot_link.client`，所以复制到 Ubuntu 时要保留 `host_control` 与 `ros2_ws` 的并列关系。

### ros2_ws 内部

| 文件或子目录 | 作用 |
| --- | --- |
| `run.sh` | 加载 ROS 2 Jazzy 和当前工作空间的环境，加入同仓库 host_control 的导入路径，再执行 ros2 run |
| `src/` | ROS 工作空间的源代码目录 |
| `src/f401_robot_bridge/package.xml` | ROS 包名称、依赖和构建类型声明 |
| `src/f401_robot_bridge/setup.py` | Python 包安装配置；把 network_bridge、keyboard、keyboard_window 注册成可执行入口 |
| `src/f401_robot_bridge/setup.cfg` | 指定 ROS Python 可执行脚本的安装目录 |
| `src/f401_robot_bridge/resource/f401_robot_bridge` | ament 包索引标记，让 ROS 工具能发现这个包 |
| `src/f401_robot_bridge/f401_robot_bridge/` | 真正的 Python 节点与状态逻辑源码 |

包内源码的职责：

- `bridge_node.py`：`NetworkBridge` 节点。订阅 `/cmd_vel`，提供 connect/arm/disarm 服务，调用 TCP 客户端，并发布 `/joint_states`、`/robot/state`。
- `control_state.py`：与 ROS 环境分离的指令状态逻辑，检查目标、使能、时间和单位，换算真实四轮反馈。
- `keyboard_node.py`：终端调档节点，持续发布当前档位的 ROS 运动消息，目标变化时打印速度。
- `keyboard_window.py`：Tk 窗口键盘节点，获取按下、松开、焦点事件并发布 ROS 消息。
- `hold_state.py`：终端和窗口共用的正负档位，以及窗口的松键、重复按键和焦点处理。
- `__init__.py`：把目录声明为 Python 包。

在 Ubuntu 中执行 `colcon build --symlink-install` 后，还会出现 `build/`、`install/`、`log/`。这些是构建中间文件、可被 source 的安装环境和构建日志，源码继续维护在 `src/`。

### tests 内部

| 路径 | 验证对象 |
| --- | --- |
| `motor4/` | 四轮映射、编码器、PWM、PI、保护、麦轮公式以及本地动作/路线模式 |
| `remote_control/` | 真实 C 遥控模块的握手、会话、序号、CRC、超时、速度指令和遥测 |
| `test_bridge_state.py` | ROS 与串口之间的速度单位、指令时效和四轮反馈换算 |
| `test_hold_state.py` | 窗口按下/松开、按键重复、焦点和事件处理时间规则 |
| `test_ros_bridge.py` | 用替代 ROS 对象测试节点、服务与键盘发布逻辑 |

`tests/motor4`、`tests/remote_control` 里的 `.c.txt`、`.h.txt` 是供测试复制使用的 C 测试代码和 HAL 替代头文件。保留 `.txt` 后缀是为了让 STM32 工程不会把这些电脑端测试当成固件源码一起编译。`run_tests.py` 在临时目录中复制并编译它们。

## 二、STM32 关键源码怎么分类

| 文件 | 职责 | 学习重点 |
| --- | --- | --- |
| `main.c` | 初始化、启动控制节拍、主循环与回调连接 | 程序怎样启动；主循环和中断怎样配合 |
| `robot_app.h/.c` | 当前模式选择；本地按键/路线测试；模式 7 转入遥控 | 条件编译、状态机、非阻塞计时 |
| `remote_control.h/.c` | STM32 串口遥控协议，接收缓冲、校验、命令消费、遥测发送 | 串口字节怎样变成运动目标 |
| `mecanum.h/.c` | 车身前进/横移/旋转要求到四轮目标 RPM 的换算 | 车身坐标、轮序、几何参数和等比例限幅 |
| `motor4.h/.c` | 四路电机配置、编码器测速、PI、PWM 和故障状态 | 目标轮速怎样变成硬件输出 |
| `tim.h/.c` | TIM1 PWM、TIM2/3/4/5 编码器、TIM9 控制周期 | 定时器时钟、PSC/ARR/CCR 和引脚复用 |
| `gpio.h/.c` | 普通方向输出、STBY、按钮和 LED 配置 | 输入/输出模式、初始电平、按键极性 |
| `usart.h/.c` | USART2 参数、引脚、接收中断和 HAL 回调转交 | 115200/8N1、中断收字节、主循环解析 |
| `stm32f4xx_it.h/.c` | 处理器与外设中断入口 | IRQ Handler → HAL → 应用回调的调用链 |
| `stm32f4xx_hal_msp.c` | HAL 底层硬件支持初始化 | 外设时钟、系统配置和电源模块准备 |
| `main.h` | 引脚标签及应用共用声明 | GPIOC + GPIO_PIN_0 就是 PC0 等宏映射 |
| `stm32f4xx_hal_conf.h` | HAL 模块开关和库级配置 | 编译哪些 HAL 功能，通常由 CubeMX 管理 |
| `system_stm32f4xx.c` | 进入 main 前的芯片系统初始化和 SystemCoreClock 支持 | SystemInit 与 main 内 SystemClock_Config 的分工 |
| `syscalls.c` | 为 C 标准库提供最小底层系统调用适配 | 裸机环境中标准输入输出等接口的底层支撑 |
| `sysmem.c` | 为 C 库堆分配提供 `_sbrk` 支持 | 堆的增长边界、链接符号与栈预留 |
| `motor.h` | 早期单电机版本留下的接口声明 | 当前四路应用调用 motor4；此文件不是现行调参入口 |
| `Startup/startup_stm32f401retx.s` | 复位入口和中断向量表 | 设置栈、调用 SystemInit、准备数据区、调用 main |

## 四、建议的阅读路线

从你最近关心的“ROS 话题怎样变成串口数据”开始：

1. `ros2_ws/run.sh` 和 ROS 包 `setup.py`：找到启动命令实际调用的入口。
2. `bridge_node.py`：找订阅注册、`_on_stamped` 回调和 `_tick` 定时发送。
3. `control_state.py`：看 `linear.x/y`、`angular.z` 怎样变成 mm/s、mrad/s 整数。
4. `host_control/robot_link/client.py`：看这些字段怎样组织为 JSON 请求。
5. `host_control/robot_link/gateway.py`、`protocol.py`：看 Mac 怎样排列串口字段并加 CRC。
6. `Core/Src/remote_control.c`：看 STM32 怎样解析 V 指令并调用麦轮接口。
7. `mecanum.c`、`motor4.c`：看车身要求怎样变成轮速，再变成 PWM。
8. 反向追踪遥测：STM32 的 T 帧 → Mac 的结构化 wheels 数据 → ROS 的 JointState。

从单片机基础开始，则按 `main.c → robot_app.c → remote_control.c → mecanum.c → motor4.c → tim.c/usart.c/gpio.c` 阅读。已有板上默认时钟为 HSI 经 PLL 得到 84MHz；TIM9 每 10ms 调用控制流程，UART 主循环负责命令解析与遥测发送。

- [遥控协议](remote-control-protocol.md)：串口 H/A/V/S、ACK/T 帧和网络 JSON 字段约定。

在工程根目录执行已有电脑端测试：

```bash
python3 tests/motor4/run_tests.py
python3 tests/remote_control/run_tests.py
python3 -m unittest discover -s host_control/tests -p 'test_*.py'
python3 -m unittest discover -s tests -p 'test_*.py'
```

C 仿真脚本需要可用的 clang；Python 节点测试使用替代对象，可在未安装 ROS 的电脑运行。电脑测试覆盖软件行为，Ubuntu 中实际的 ROS 环境和板上电机运行另按上手步骤验证。
